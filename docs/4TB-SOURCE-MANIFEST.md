## Rebuilding the 0.2.1 candidate

Use Node 24 LTS and the existing dependency lockfiles. Configure each explicit
source path in `.env.4tb`, then check out its pinned revision with a clean
worktree. If a different Git executable is needed, set `EASYLAB_GIT_BINARY`.

```sh
npm run preflight:modules
npm run sync:apps
npm run build
npm run preflight:modules:artifacts
```

The npm commands load `.env.4tb`. Strict sync always rebuilds the frontend
assets before copying them; a copy-only strict sync is rejected. The generated
`apps/module-sources.json` records the Suite version, each module's repository
and full revision, and a SHA-256 digest of its bundled files. Artifact preflight
checks these records and digests, so a stale or changed module cannot silently
be packaged under the current source pin. Python runtime caches are excluded.

Notebook's **Open in browser** button opens only the Suite-owned
`http://127.0.0.1:8030/` route, without forwarding embedded-browser flags or
OAuth parameters. Use a Google Web application client whose authorized
JavaScript origins include that exact origin. Keep Suite open while using the
browser client. The standalone source's Android remote-write safety gate is
unchanged; this candidate does not enable a new OAuth flow or cloud service.

Real Google login/permission, notebook edit/sync and exported-file round trips
remain pending until a user-controlled browser session completes those checks.
The source below retains the earlier 0.1.19 packaging history.
